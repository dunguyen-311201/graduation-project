# ADR-0014: Move the mobile app to Expo with a development build

- **Status:** Proposed
- **Date:** 2026-10-31
- **Related:** ADR-0011, ADR-0013, NF-08, roadmap G5

## Context

`sosapp/` is a bare React Native 0.71 project (2023) with hand-maintained `android/` and `ios/` folders. Upgrading it to a current React Native means re-applying several years of native template changes by hand. Several dependencies are unmaintained (`react-native-push-notification`, `react-native-config` on the new architecture), and React Native Firebase v22+ dropped the namespaced API the app used. The owner wants the app on Expo.

The app needs native modules that Expo Go does not contain: React Native Firebase (Auth with phone OTP, Firestore, Messaging) and Google Maps.

## Decision

Rebuild `sosapp/` as an Expo SDK 58 project (React Native 0.88, React 19, new architecture) using a **development build** (`expo-dev-client`) and Continuous Native Generation.

- `android/` and `ios/` are generated by `expo prebuild` from `app.config.ts` and are not committed.
- Native setup is declared through config plugins: `@react-native-firebase/app`, `/auth`, `/messaging`, `expo-build-properties` (static frameworks on iOS), `expo-location`, `expo-image-picker`, `@react-native-community/datetimepicker`; the Google Maps key is set with `android.config.googleMaps.apiKey`.
- Keep React Native Firebase (now v27, modular API) rather than the Firebase JS SDK, because phone auth and FCM need native SDKs. Firebase instances are created once in `src/services/firebase.ts`.
- Replace libraries with Expo modules where one exists:

| Before | After |
| --- | --- |
| `react-native-config` | `EXPO_PUBLIC_*` variables from `.env` (`src/constants/env.ts`) |
| `@react-native-community/geolocation`, `react-native-geolocation-service`, `react-native-permissions` | `expo-location` |
| `react-native-device-info` | `expo-device` |
| `react-native-linear-gradient` | `expo-linear-gradient` |
| `react-native-image-picker` | `expo-image-picker` |
| `react-native-push-notification` (unused) | removed; FCM via `@react-native-firebase/messaging` |
| `@react-native-google-signin/google-signin`, `react-native-uuid` (unused) | removed |
| Storybook 6 | removed for now; re-add Storybook 9 for React Native if needed |
| React Navigation 6 | React Navigation 7 (`unmountOnBlur` removed; screens use realtime listeners) |

- `google-services.json` is per Firebase project and git-ignored; EAS Build receives it as a file environment variable `GOOGLE_SERVICES_JSON`.
- Package manager: npm (`package-lock.json`) inside `sosapp/` until the pnpm workspace from ADR-0008 lands; Expo then needs `node-linker=hoisted` in `.npmrc`.

## Options considered

| Option | Pros | Cons |
| --- | --- | --- |
| Expo + dev client + prebuild (chosen) | Upgrades become `npx expo install --fix`; native config is code; EAS cloud builds without a local Android SDK; Expo modules replace unmaintained libs | One-time migration; native folders are regenerated, so manual native edits must become config plugins |
| Upgrade bare React Native in place | No tooling change | Large manual native diff (0.71 to 0.88), unmaintained libs remain |
| Expo Go only | Fastest start | Cannot run React Native Firebase or Google Maps; not viable |

## Consequences

- Positive: the native layer is reproducible from `app.config.ts`; typecheck and Metro bundling can run in CI without Android tooling; dependency versions are pinned to what the SDK supports.
- Negative: developers must build the dev client once (locally or on EAS) and rebuild after native changes; `onUserChanged` is not in the modular auth API, so `useAuth` reloads the profile explicitly after sign-up and profile updates.
- Follow-up: add a notification icon, EAS build profiles (`eas.json`), Jest with `jest-expo` and React Native Testing Library (test-strategy T-MOB cases), and `npx expo lint` in CI (G5).
